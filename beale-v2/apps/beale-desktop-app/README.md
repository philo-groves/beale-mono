# Beale desktop preview

The desktop writes timestamped diagnostics to `logs/desktop.log` beneath `BEALE_V2_HOME` or `~/.beale/v2` and prints the path at startup. The file rotates at 5 MiB with three backups; errors also appear on stderr. Connection changes and session load or turn failures are recorded without prompts or transcripts.

Saved peer graph turns can contain up to 4,096 tool summaries across the returned transcript. Adjacent base, Webfetch, Surfaces, Findings, Memories, Runbooks, Graphs, Agent Feedback, and Goal Mode calls appear as one expandable row between commentary or reasoning entries, with counts by tool type; standalone calls show their available input or goal state. Delivered graph messages appear as tool-like activity in the parent or child transcript. Collapsed completed work hides tool activity, commentary, and reasoning summaries while keeping the agent's final message visible. The desktop keeps live activity expanded when a turn or reload fails and retains the current transcript on a failed reload.

Features includes optional Webfetch with a single `webfetch` tool for web search and readable page retrieval. It starts disabled, supports workspace scoping, and applies to main agents and Graphs subagents. Enable it in Extensions > Features.
Graphs also offers Discovery and Validation, Concurrent Research Pipeline, and Sequential Research Pipeline peer flows. Sequential setup includes a minutes-per-stage field (60 by default); Goal Mode and Repeat are unavailable for that circular run. Each top-level role has a model, separate saved turns and context, and can spawn specialist subagents without blocking its next step. It can list their status and activity age, inspect live or saved transcripts and tool calls, message them, or stop them; children can inspect or message siblings in that role group. Handoffs queue bounded tasks for connected peers. Concurrent recipients can run alongside the sender; sequential recipients wait for their stage, and downstream stages advance early when their queues empty. Peer sessions appear in Home as soon as work starts; header tabs show each role's transcript, working state, and handoffs, and new prompts address the selected role. Live tool activity can be expanded to inspect each call's arguments and first result page while a turn runs; remaining output is paged after completion.

Features includes optional Agent Feedback with one on-demand `agent_feedback` tool. It has no desktop report viewer; the app-server writes reports to its private `agent-feedback.jsonl` for development review.

The optional Memories feature appears in Features with four on-demand, read-only agent tools. The app-server processes completed main and subagent turns asynchronously using the configured default small model. Session transcript search reads the existing host transcript; long-term entities and sourced assertions live in a separate local `memories.sqlite`. Host-authenticated status, retry, and disabled-workspace clear routes are available through protocol 2.12.

The Extensions Plugins view opens on All Plugins; Available shows only uninstalled plugins, and Installed shows only installed plugins. Cards show a small squircle mark beside each name. The details area lists Skills, Scripts, References, and Assets above a divider, then MCP Servers, Tools, Prompt Templates, and Resources. Skill file counts come from the validated package; installed MCP inventories are discovered at server launch. Cards fill a responsive grid with up to four columns. Its info button opens a selectable, scrollable view of the plugin's `plugin.json` manifest. The desktop fetches the validated manifest from the app-server when connected and can show its embedded manifest for bundled plugins while offline. An installed Plugin card has a workspace dropdown beside its toggle. It starts at All Workspaces; select individual workspaces to limit where the Plugin applies, or deselect all for No Workspaces.

The app-server assigns workspace-local S1, S2, and subsequent IDs without reuse. Schema 7 surfaces contain only an ID, required definition, relationships, and revision lineage at the top level. The definition records type, name, locator, scope, review state, description, exclusion reason, and typed evidence references. Existing schema 3 through 6 manifests migrate on read; old parent IDs become explicit `contains` relationships and old narrative fields become a description. The next write persists schema 7. AI imports carry temporary keys and relationship references through the reviewed draft, and the host resolves them to short IDs on creation. An explicit out-of-scope surface or rule still excludes the covered target or third party. The v2 preview does not yet perform first-touch review or live-target operations.

## Visual system and review

Home is a Research desk: New research and Create workspace actions, Continue research with the five most recently active sessions (title, workspace, and relative activity time), and workspace cards with directory, session count, and last activity in one or two columns. Home uses only the workspace and session lists the sidebar already loads. Its main content shows the shared scrollbar when the page overflows. Per-view sidenav lists also show that scrollbar on overflow; Home keeps its Workspaces/Tasks selector above the scrolling list, and Automations keeps its primary action above the run list. The Beale title sits in the header above the sidebar content.

Dark uses neutral black and charcoal surfaces, silver accents, and neutral text. Semantic status colors remain distinct from the interface palette. Dark and Midnight toggles dim their off state, so the lit accent track marks an enabled control.

Single-line text that overflows its box fades out over its trailing 2.5em (`FadeText::fade_truncate` in `src/design.rs`); the desktop never ends text with an ellipsis. Card descriptions limited to a few lines clip with a bottom fade only when the measured text needs more lines (`design::faded_lines`). Truncated session titles, workspace names, and card text show the full text on hover.

Home, Settings, Tracking, Extensions, Automations, and Fleet begin with their controls or content instead of repeating the header and sidenav hierarchy in a breadcrumb and introductory description. Other page headers combine parent context and title in one breadcrumb row: muted 13px parent labels, a subtle chevron, and the current view as the prominent final crumb. Titles fade when space is constrained. New Research retains its workspace picker in the final crumb, with a dropdown chevron. Workspace pages switch between Surfaces, Findings, Rules, and Settings with labeled segmented tabs beside the title, falling back to icon-only tabs with hover names when fewer than 280px would remain for the title. The header workspace tab stretches up to 360px so the name fits beside its view label.

Findings cards lead with an impact chip colored from the recorded screening score (70 and above error, 40 and above warning, otherwise neutral; unscored records stay neutral), followed by reachability, the record ID, title, summary, surface count, evidence count, and update date. Records past Candidate without supporting evidence show the evidence count in the warning color. Surfaces relationship labels sit centered on their own edge, avoiding other edges where a clear spot exists; out-of-scope edges use an even dash measured along the curve and end in a solid run that meets the arrowhead.

View tabs use shared inset segmented controls with 32px targets, raised selected surfaces, subtle borders, and consistent hover states. Contextual 15px icons share the label color, a 6px gap, and disabled opacity; provider tabs use their existing monochrome marks. Labels retain the same size and weight when selection changes. Providers reflow to balanced three- or two-column groups using measured label widths and the selected text size; other groups wrap as needed. The Default provider and Theme controls share their respective tab rows when both fit with a 16px minimum gap, otherwise they sit below. The fit includes the selected value label and interface font. Workspace setup keeps unavailable steps visibly disabled.

`src/token_charts.rs` supplies shared token metrics, bar charts, mix rings, and model rankings for Tracking and session Insights. `src/design.rs` supplies shared accent, control, card, eyebrow, subtitle, and empty-state treatments. `src/appearance.rs` owns the four semantic palettes and resolves older neutral/status literals through those palettes. Standard controls are 32px high, sidenav navigation rows share a 34px height, cards use 12px corners, and page sections use a 24px gap. Per-view sidenav titles sit in the header above the sidebar content and share a 16px semibold muted style. Page headings are 24px; form labels and supporting text preserve the user's selected font and text-size preference. Existing palette overrides remain compatible, and editable swatches render their literal values.

The sidenav collapses when the window narrows below 1000px and returns when it widens again, unless the operator toggles it in between; it can still be opened in a narrow window. Workspace form rows place their control below the label when the two cannot share a line. Canvas occupies the available content area when less than 680px remains after navigation; closing Canvas returns to the original view. At that width, session telemetry sits above the transcript. Tall dialogs scroll their body while keeping titles and actions in the window. Provider actions wrap instead of overflowing their card.

The script renders all four themes using `BEALE_UI_PREVIEW` plus Rune's `--snap`, captured after one virtual second (`--at`, default `1`) so width-driven layout such as the sidenav collapse has settled. Preview initialization bypasses saved desktop state and app-server polling, uses synthetic research and host fixtures, and isolates its data directory under the output folder. Without `--snap`, the preview variable has no effect. PNGs and optional Pillow contact sheets remain in ignored `target/` directories. Build before running the audit; Windows locks the preview executable while each snapshot is rendered.
