# Beale desktop preview

The Extensions Plugins view opens on All Plugins; Available shows only uninstalled plugins, and Installed shows only installed plugins. Cards show a small squircle mark beside each name and frame the Skills and MCP Servers (Tools) rows with dividers; tool counts are displayed as servers (tools). Installed plugin counts come from live MCP discovery. Cards fill a responsive grid with up to four columns. Its info button opens a selectable, scrollable view of the plugin's `plugin.json` manifest. The desktop fetches the validated manifest from the app-server when connected and can show its embedded manifest for bundled plugins while offline. An installed Plugin card has a workspace dropdown beside its toggle. It starts at All Workspaces; select individual workspaces to limit where the Plugin applies, or deselect all for No Workspaces.

This Rust desktop client uses [Rune](https://github.com/anomalyco/rune), pinned to a specific upstream commit in `Cargo.toml`. The v2 workspace uses Rust 1.99.1 to build Rune directly. The initial window opens Home with a v1-style sidebar containing the Beale wordmark, New Research and Quick Chat actions, and a Workspaces section. Quick Chat remains unavailable; the Home main panel says "No workspace is selected." until a workspace view opens. No app-server selector is shown. The Settings sidenav lists General, Appearance, Providers, and Archive; Appearance and Providers have settings views in this preview. Appearance has Colors and Typography tabs. Colors offers the v1 Light, Dark, Cream, and Midnight themes and per-theme Heat Palette colors. Typography has a Font Options form with dropdowns for the Beale or system interface font and Extra Small (80%), Small (90%), Standard (100%), Large (110%), or Extra Large (120%) text size, followed by a Sample preview. Existing Compact preferences load as Small at the same 90% scale. Changes apply live, and the desktop stores them in `desktop-appearance.json` under `BEALE_V2_HOME` or the default v2 host directory. The Providers view has Anthropic, OpenAI, OpenRouter, xAI, Z.ai, and Custom tabs; Anthropic opens by default when navigating to Providers. Built-in provider tabs show Authentication and Default Models; Custom manages named OpenAI-compatible APIs, their model IDs, and host-saved API keys. Authentication and model controls connect to the host. The header toggle collapses the sidenav while retaining the icon rail. The header has a contextual title and Windows minimize/maximize/close controls. On Windows, the borderless frame has a theme-colored 1px edge and supports dragging its edges and corners to resize. Windows 11 uses a system-drawn border that follows its rounded corners; older Windows versions use an inset Rune border and retain their native corner shape. On macOS, Rune retains native traffic lights; on Linux, the system titlebar remains. The window has an 840 × 600 minimum content size. When enabled in Features, Fleet opens with App Servers, Browsers, and Virtual Machines sidenav sections. Browsers has All, Detected, and Manually Added tabs; the other sections have All, Available, and Enabled. App Servers lists the local app server first, then direct Tailscale connections in compact cards with OS vendor marks, host or desktop alias, contract version, condition, and an information dialog. Remote cards have connection toggles. The local card has an authenticator QR button; other desktops pair with its current six-digit code and Tailscale link. The plus icon offers Manually Add and Tailscale Import. Import lists local tailnet devices, allows selection of an online device and Serve HTTPS port, and still requires the remote authenticator code before saving. The desktop saves remote endpoints and tokens in its private `desktop-fleet.json`; Browsers lists installations detected on the local and connected remote app servers. The browser plus button adds a named executable path on a selected host; manually added entries can be removed. Browser cards use bundled color logos for the seven supported browser names, with a globe for other manual names. Their toggles and workspace selectors save enabled state and scope on the owning app server; browsers start enabled for all workspaces. Virtual Machines lists Hyper-V guests from reachable Windows app-servers in cards with host, state, source, and generation. The tabs filter all, running, and not-running guests. Each footer has an enabled toggle and workspace selector, then Can Run and Can Clone allowance icons. Both allowances default off; the owning app-server saves them. VM execution and cloning are not exposed yet. The conditional Fleet rail icon sits below the standard icons after a divider and is hidden while Fleet is disabled. Automations remains unavailable in this preview.

When enabled, the workspace Surfaces tab uses a connected-node icon and shows a Rune network of typed nodes, parent links, and labeled connections. Knowledge Base uses a separate book icon. Each surface node has one outline colored grey to red by update count relative to the most edited surface. Surface names appear beneath nodes; hovering reveals full node details and connection labels. Selecting a node shows its ID, definition, update time, and recent lineage. Clicking empty network space closes that detail panel; clicking another node switches it. The saved editor updates definitions and relationships; Save Changes records their revisions in the workspace manifest.

Typography follows the v1 UI and monospace font stacks. The desktop bundles the Inter faces used by the Beale font choice and loads system faces for the System choice. The bundled Inter files come from the pinned Rune revision under the [SIL Open Font License](assets/fonts/Inter-LICENSE.txt).

In Appearance, the Color Theme menu beside the Colors and Typography tabs selects the desktop theme. The Colors view shows the selected theme's preview, name, and description above its Heat Palette. A Theme Palette form below it exposes the theme's surfaces, text, borders, gradient, and status colors. Click a color preview to open an in-window selector for hue, saturation, and brightness; use the adjacent hex field for exact values. Edits apply live to the selected theme and persist locally. A revert icon appears beside each changed heat or theme color and restores only that color's default.

Settings content scrolls within its panel. A scrollbar appears flush with the panel's top, bottom, and right edges when the selected view exceeds the available height. Use its up and down triangles for short steps, click its track, or drag its thumb to move through the view. Notched mouse-wheel steps glide, while precise trackpad scrolling follows the input directly.

Navigation, settings, and header icons use the Lucide shapes from v1 at pixel-aligned sizes. Their license is in [src/LUCIDE-LICENSE](src/LUCIDE-LICENSE).

The desktop uses the v1 Beale app icon from `assets/app-icon.png`. Windows embeds an `.ico` variant with tighter transparent bounds in the executable and loads it for the window and taskbar; macOS uses the original PNG for the Dock and app switcher.

On Windows, the desktop saves its restored window position and size plus maximized state in `desktop-window.json` beside `desktop-appearance.json`. Closing and reopening restores the saved placement. A saved position on a disconnected display falls back to the default window placement.

Provider titles use the OpenAI Blossom carried over from v1 and the Grok logomark from [Grok's site](https://grok.com/images/favicon.svg). The marks identify the configured services; see the [OpenAI](https://openai.com/brand/) and [Grok](https://x.ai/legal/brand-guidelines) brand guidelines.

The Settings sidenav starts at 292px and resizes by dragging its right edge between 240px and 420px. The header title separator follows that edge and stays clear of the sidebar toggle and view-history arrows when the sidenav is collapsed. The header arrows move backward and forward through settings sections and provider and appearance tabs; unavailable directions are muted.

New Research opens from the Home sidebar. Its first pass shows a compact multiline composer anchored at the bottom of an otherwise blank view, with a lead model selector in the composer's lower row. The selector opens a three-row Provider, Model, and Effort menu with options beside the active row. It lists models from each configured provider's active credential source and starts from the saved lead provider and model default. Effort starts at High and is shown in muted text beside the selector chevron. Model and effort choices belong to this draft and do not change provider defaults. The current model catalog does not include supported effort levels, so the draft offers the v1 effort levels without model-specific filtering; the selected model is used for text turns sent through the app-server. The composer retains its text while navigating between views.

The Home sidebar has a Workspaces/Tasks dropdown above its collection area. Workspaces shows the existing list, a bordered plus button beside the dropdown for creating a workspace, and a bordered search icon at the far right. Hovering anywhere on a saved session row shows its full title, time since its last saved message, and workspace name beside the sidebar. Hovering a workspace row shows its name, session count, and directory. During a New Research draft, an active italic New Session row appears beneath its selected workspace and returns to the same draft when clicked. Tasks is an empty section for now.

The New Research composer prompts "Research with Beale" and has a ribbon above it with a folder icon, selected workspace name, and menu chevron. The workspace menu lists saved workspaces and changes only this research draft. It initially uses the last opened workspace when available, otherwise the first listed workspace; with no saved workspaces, the ribbon shows Select Workspace without an active menu. Its repeat icon opens draft presets for no repeat or every minute, hour, day, week, or month. A green dot appears on the Repeat button when a preset other than No Repeat is selected, and on the Goal Mode button when enabled for the draft. These selections are retained while navigating the draft; repeat scheduling is not connected to the app-server yet.

The desktop displays OpenAI catalog names with spaces in place of dashes in both Providers and New Research, including when a running app-server sends older dashed labels. Model IDs remain unchanged.

Home's Add workspace button opens the New Workspace draft at Import. None (the default) continues to manual setup. Research Kit shows an unavailable placeholder until kits exist. Custom Instructions sends the supplied research context to the configured default large model; the host may use read and bash tools to gather details, streams progress in the shared Quick Chat panel, which can cancel the import, and fills a draft of name, guidance, surfaces, and rules for review in General. The model records general scope in Rules and may suggest surfaces when the supplied context supports them; the user chooses the directory separately. General, Surfaces, and Rules views use the same form styling and scroll behavior as Settings. General shows the name and directory as values under Basic Information. Edit buttons open text dialogs for both, and a folder button opens the native directory picker. Workspace guidance remains editable; paths under the user home display with ~/. There is no Research Subject field. Surfaces has separate In-Scope Surfaces and Out-of-Scope Surfaces lists; each entry records its type, creator, and scope. The plus button beside either list heading opens a centered dialog titled Add an In-Scope Surface or Add an Out-of-Scope Surface. The clicked list fixes the scope; the dialog has type, identifier, optional locator, parent, context, and scope fields, validates entries in place, and closes with Cancel, the close button, Escape, or an outside click. The desktop marks entries added during creation as user-created and gives exclusions the reason "Set at workspace creation" without asking for one. Rules can record operating constraints. Next validates the required general fields; surfaces are optional when a Rule records the authorized scope. The New Workspace Cancel button opens a confirmation dialog; Keep Editing, Escape, the close button, or an outside click preserves the draft, while Discard Workspace clears it.

When connected, Create Workspace sends the draft over the authenticated v1.8 protobuf route. The app-server validates and creates the workspace, then returns its canonical ID, name, and directory. The desktop keeps the draft open with an error if creation fails, and returns Home after success. Home loads the app-server's workspace registry on connection and refreshes it about every ten seconds. Clicking a workspace opens Rules by default. Surfaces appears when its feature is enabled for that workspace; Settings and Rules remain available. General, Surfaces, and Rules load through separate host contracts and can be edited and saved independently. General uses a name edit dialog and an editable guidance field; existing workspace directories remain fixed. Surfaces can be added, edited, or removed in their scope lists. The trash icon asks for confirmation before removing a Surface from pending edits; Save Changes applies that deletion to the workspace. Editing a Surface's type or identifier keeps its stable ID and records the edit as user-created. Workspace Rules lists the recorded rules, with a plus button at the form title that opens an Add a Rule dialog; rules can also be removed from the list. A stale save reports a revision conflict and offers Reload Workspace. Campaign shows an empty state until individual campaign features are enabled. Workspace content uses the v1 1300px wide container. New Research opens the text session view with a saved transcript after the first completed turn.

The app-server assigns workspace-local S1, S2, and subsequent IDs without reuse. The schema 5 manifest stores specific surface types, typed locators, parent links, names, summary and security context, scope basis and descendant coverage, source, labeled relationships, and revision lineage. Existing schema 3 and 4 manifests are mapped to short IDs on read and upgraded to schema 5 on the next write; old IDs remain as aliases for client updates. AI imports carry temporary keys and references through the reviewed draft, and the host resolves them to short IDs on creation. First-touch review may establish relevance when a surface contributes directly or secondarily to the workspace's scope, including supporting binaries, utilities, and parsers. An explicit out-of-scope surface or rule still excludes the covered target or third party. The v2 preview does not yet perform first-touch review or live-target operations.

Settings sections, their view renderers, and form headings and rows are defined in typed metadata near the top of `src/main.rs`. A shared form renderer supplies headings, cards, and row separators; row functions retain typed provider and appearance actions. Heat and theme palette rows use their existing color-field catalogs.

Run from `beale-v2/`:

```text
cargo run -p beale-desktop-app
```

Rune can render a headless snapshot for layout review:

```text
cargo run -p beale-desktop-app -- --snap target/beale-desktop-snap.png --scale 1
```

The desktop checks the app-server's versioned protobuf health endpoint, retries every two seconds, and offers `--check-connection` and `--provider-status` commands. OpenAI, xAI, Anthropic, and Z.ai support same-device subscription sign-in and API keys; OpenRouter uses API keys. Anthropic sign-in opens the official Claude terminal, while Z.ai sign-in opens ZCode Model Settings. The Custom tab manages named OpenAI-compatible chat APIs, optional keys, and model IDs, with model discovery through the app-server. Each configured provider can become the Default Provider. Built-in providers load their model catalogs and save lead/small defaults; custom providers save those defaults with their definition. Provider and model choices use anchored menus. The app-server owns credentials and returns only status and model metadata to the desktop.
New Research sends composer text through the selected provider. Completed turns, reasoning summaries when supplied, and tool activity appear in the scrollable transcript and persist in app-server storage. Sessions can be reopened beneath their workspace in the Home sidebar.

In a session, the list icon immediately left of Canvas opens an inset Session sidenav card at the top right. It opens automatically after a successful memory, lead, finding, runbook, or surface creation, or a graph subagent delegation; opening Canvas closes it. Both panels slide in and out. The card grows with its content. Below the small regular-weight heading and duration, an icon row shows compact session tokens on the left and muted input/output counts on the right; another shows the cache hit rate to one decimal place on the left and cached tokens on the right. Row accessibility labels retain exact counts, the cache-rate denominator, and telemetry coverage. Token totals include main and subagent calls. Calls without cache telemetry are excluded from the cache-rate denominator; an unavailable rate is shown as a dash. The duration counter sums completed turn durations from app-server storage and the current running turn, excluding time between turns. The app-server totals include turns outside the recent transcript window.

The Session heading has a chart shortcut that opens the token popout; a broader visualization modal is reserved for a later update. Hovering either usage row opens an interactive chart menu to its left. The menu stays open while the pointer crosses to it and closes after the pointer leaves both the row and menu. The token menu plots cumulative total, input, and output tokens; the cache menu plots cache hit rate and cached input tokens. Both show five-minute active-work snapshots, include the latest partial interval, and let the user step through values. Calls saved before per-call work offsets were introduced appear at their completed-turn boundary.

The Features view opens on All Features; Available shows only disabled features, and Enabled shows only active features. It lists Goal Mode and Fleet as native features, both disabled by default, and shows their prompt-extension capability and model-facing tool count. Enabling Fleet shows its rail icon and divider; disabling it hides both and returns an open Fleet view to Home. Each Feature card has a squircle mark beside its name, dividers around its stat rows, and an info button that fetches additional details; Goal Mode shows its reusable prompt extension there. Feature enablement and plugin installation use toggle controls. Enabled Feature cards have a workspace dropdown beside the toggle with the same All Workspaces, individual selection, and No Workspaces choices as Plugins. Enable Goal Mode there to show the target icon beside Repeat in New Research's ribbon for applicable workspaces. Its menu has a checkbox toggle for the current draft and optional positive-integer limits for max turns and max duration in minutes; blank limits mean unlimited. When enabled for a session, the app-server keeps the initial prompt as the objective and streams each saved continuation turn back to the transcript. A completed, waiting, or paused goal displays its status below the transcript; a user message can resume a waiting or paused goal unless a configured limit was reached. Disabling the feature pauses active goals. Older turns remain saved when the recent transcript window rolls forward. Ordinary sessions and Quick Chats do not expose the Goal Mode tool.

Fleet browser cards show Detected or Added in a Source stat row. The star in each card footer marks the preferred browser for its app-server; selecting another available enabled browser saves that host's choice. Before an explicit choice, the host uses its OS default browser when it is present in Fleet, then an available enabled browser.

Tracking is a native feature disabled by default. Enabling it shows a conditional icon below the main rail destinations. Its dashboard charts the past seven days of observed subscription remaining and daily stacked model usage from Beale research sessions, with Duration and Tokens controls. Model usage includes main and graph subagent roles. The desktop refreshes the host history while Tracking is open; missing provider token counts are excluded from token totals and reported beneath that chart.

Surfaces is a native feature disabled by default. Enabling it for a workspace shows its diagram and supplies four model tools for add, edit, get, and query operations. Disabled sessions and Quick Chats use Rules for general scope context without injecting surface records or tools. The diagram shows a single outline from grey to red based on each surface's update count relative to the most edited surface. The details panel shows update time and recent revisions. Deleted surfaces retain their lineage in the workspace manifest.

Knowledge Base is a native feature disabled by default. When enabled for a workspace, its tab searches memories and claims together, filters Findings and Memories, and opens evidence, links, and revision details. Eight model tools provide compact query and get reads plus separate memory and claim writes. A sink is a memory role, not a finding stage. Claim promotion to observed requires a cited host-validated read or bash result; reproduced and verified remain unavailable pending a Knowledge-owned verifier. The feature does not require other optional features.
