# Beale desktop preview

This Rust desktop client uses [Rune](https://github.com/anomalyco/rune), pinned to a specific upstream commit in `Cargo.toml`. The initial window opens Home with a v1-style sidebar containing the Beale wordmark, New Research and Quick Chat actions, and a Workspaces section. Quick Chat remains unavailable; the Home main panel says "No workspace is selected." until a workspace view opens. No app-server selector is shown. The Agent Settings sidenav lists General, Appearance, Providers, and Archive; Appearance and Providers have settings views in this preview. Appearance has Colors and Typography tabs. Colors offers the v1 Light, Dark, Cream, and Midnight themes and per-theme Heat Palette colors. Typography has a Font Options form with dropdowns for the Beale or system interface font and Extra Small (80%), Small (90%), Standard (100%), Large (110%), or Extra Large (120%) text size, followed by a Sample preview. Existing Compact preferences load as Small at the same 90% scale. Changes apply live, and the desktop stores them in `desktop-appearance.json` under `BEALE_V2_HOME` or the default v2 host directory. The Providers view has OpenAI and xAI tabs above the current provider's Authentication and Default Models sections. Authentication and model controls connect to the host. The header toggle collapses the sidenav while retaining the icon rail. The header has a contextual title and Windows minimize/maximize/close controls. On Windows, the borderless frame has a theme-colored 1px edge and supports dragging its edges and corners to resize. Windows 11 uses a system-drawn border that follows its rounded corners; older Windows versions use an inset Rune border and retain their native corner shape. On macOS, Rune retains native traffic lights; on Linux, the system titlebar remains. The window has an 840 × 600 minimum content size. Other rail destinations explain that they are not available in this preview.

Typography follows the v1 UI and monospace font stacks. The desktop bundles the Inter faces used by the Beale font choice and loads system faces for the System choice. The bundled Inter files come from the pinned Rune revision under the [SIL Open Font License](assets/fonts/Inter-LICENSE.txt).

In Appearance, the Color Theme menu beside the Colors and Typography tabs selects the desktop theme. The Colors view shows the selected theme's preview, name, and description above its Heat Palette. A Theme Palette form below it exposes the theme's surfaces, text, borders, gradient, and status colors. Click a color preview to open an in-window selector for hue, saturation, and brightness; use the adjacent hex field for exact values. Edits apply live to the selected theme and persist locally. A revert icon appears beside each changed heat or theme color and restores only that color's default.

Settings content scrolls within its panel. A scrollbar appears flush with the panel's top, bottom, and right edges when the selected view exceeds the available height. Use its up and down triangles for short steps, click its track, or drag its thumb to move through the view. Notched mouse-wheel steps glide, while precise trackpad scrolling follows the input directly.

Navigation, settings, and header icons use the Lucide shapes from v1 at pixel-aligned sizes. Their license is in [src/LUCIDE-LICENSE](src/LUCIDE-LICENSE).

The desktop uses the v1 Beale app icon from `assets/app-icon.png`. Windows embeds an `.ico` variant with tighter transparent bounds in the executable and loads it for the window and taskbar; macOS uses the original PNG for the Dock and app switcher.

On Windows, the desktop saves its restored window position and size plus maximized state in `desktop-window.json` beside `desktop-appearance.json`. Closing and reopening restores the saved placement. A saved position on a disconnected display falls back to the default window placement.

Provider titles use the OpenAI Blossom carried over from v1 and the Grok logomark from [Grok's site](https://grok.com/images/favicon.svg). The marks identify the configured services; see the [OpenAI](https://openai.com/brand/) and [Grok](https://x.ai/legal/brand-guidelines) brand guidelines.

The Agent Settings sidenav starts at 292px and resizes by dragging its right edge between 240px and 420px. The header title separator follows that edge and stays clear of the sidebar toggle and view-history arrows when the sidenav is collapsed. The header arrows move backward and forward through settings sections and provider and appearance tabs; unavailable directions are muted.

New Research opens from the Home sidebar. Its first pass shows a compact multiline composer anchored at the bottom of an otherwise blank view, with a lead model selector in the composer's lower row. The selector opens a three-row Provider, Model, and Effort menu with options beside the active row. It lists models from each configured provider's active credential source and starts from the saved lead provider and model default. Effort starts at High and is shown in muted text beside the selector chevron. Model and effort choices belong to this draft and do not change provider defaults. The current model catalog does not include supported effort levels, so the draft offers the v1 effort levels without model-specific filtering; session execution is not wired yet. The composer retains its text while navigating between views.

The Home sidebar has a Workspaces/Tasks dropdown above its collection area. Workspaces shows the existing list, a bordered plus button beside the dropdown for creating a workspace, and a bordered search icon at the far right. During a New Research draft, an active italic New Session row appears beneath its selected workspace and returns to the same draft when clicked. Tasks is an empty section for now.

The New Research composer prompts "Research with Beale" and has a ribbon above it with a folder icon, selected workspace name, and menu chevron. The workspace menu lists saved workspaces and changes only this research draft. It initially uses the last opened workspace when available, otherwise the first listed workspace; with no saved workspaces, the ribbon shows Select Workspace without an active menu. Its repeat icon opens draft presets for no repeat or every minute, hour, day, week, or month. These selections are retained while navigating the draft; session execution and automation scheduling are not connected to the app-server yet.

The desktop displays OpenAI catalog names with spaces in place of dashes in both Providers and New Research, including when a running app-server sends older dashed labels. Model IDs remain unchanged.

Home's Add workspace button opens the New Workspace draft. Its Foundation, Surfaces, and Rules views use the same form styling and scroll behavior as Agent Settings. Foundation collects a name, absolute directory, and optional workspace guidance; the folder button beside the directory field opens a native folder picker, while the path remains editable. Research Kit has only None, and there is no Research Subject field. Surfaces has separate In-Scope Surfaces and Out-of-Scope Surfaces lists; each entry records its type, creator, and scope. The plus button beside either list heading opens a centered dialog titled Add an In-Scope Surface or Add an Out-of-Scope Surface. The clicked list fixes the scope; the dialog has type and identifier fields, validates entries in place, and closes with Cancel, the close button, Escape, or an outside click. The desktop marks entries added during creation as user-created and gives exclusions the reason "Set at workspace creation" without asking for one. Rules can record operating constraints. Next validates the required foundation fields and at least one in-scope surface. The New Workspace Cancel button opens a confirmation dialog; Keep Editing, Escape, the close button, or an outside click preserves the draft, while Discard Workspace clears it.

When connected, Create Workspace sends the draft over the authenticated v1.8 protobuf route. The app-server validates and creates the workspace, then returns its canonical ID, name, and directory. The desktop keeps the draft open with an error if creation fails, and returns Home after success. Home loads the app-server's workspace registry on connection and refreshes it about every ten seconds. Clicking a workspace opens its Campaign view; the tabs run Campaign, Foundation, Surfaces, and Rules. Foundation, Surfaces, and Rules load through separate host contracts and can be edited and saved independently. Foundation edits the name and guidance; the directory remains fixed. Surfaces can be added, edited, or removed in their scope lists. The trash icon asks for confirmation before removing a Surface from pending edits; Save Changes applies that deletion to the workspace. Editing a Surface's type or identifier replaces its identity and records the replacement as user-created. Workspace Rules lists the recorded rules, with a plus button at the form title that opens an Add a Rule dialog; rules can also be removed from the list. A stale save reports a revision conflict and offers Reload Workspace. Campaign shows an empty state until individual campaign features are enabled. Workspace content uses the v1 1300px wide container. Session views are still forthcoming.

The future app-server surface model should use these same surface identities for scope and research tracking. First-touch review may establish relevance when a surface contributes directly or secondarily to the workspace's scope, including supporting binaries, utilities, and parsers. An explicit out-of-scope surface or rule still excludes the covered target or third party. The v2 preview does not yet perform first-touch review or live-target operations.

Settings sections, their view renderers, and form headings and rows are defined in typed metadata near the top of `src/main.rs`. A shared form renderer supplies headings, cards, and row separators; row functions retain typed provider and appearance actions. Heat and theme palette rows use their existing color-field catalogs.

Run from `beale-v2/`:

```text
cargo run -p beale-desktop-app
```

Rune can render a headless snapshot for layout review:

```text
cargo run -p beale-desktop-app -- --snap target/beale-desktop-snap.png --scale 1
```

The desktop checks the app-server's versioned protobuf health endpoint, displays its connection state in the Agent Settings sidenav, and retries every two seconds. Run `cargo run -p beale-desktop-app -- --check-connection` for a one-shot connection check or `--provider-status` to inspect configured methods and the lead provider. Both processes use `BEALE_V2_APP_SERVER_ADDR`, defaulting to `127.0.0.1:43831`; see the [workspace run instructions](../../README.md). The Providers view can start same-device OpenAI and xAI subscription sign-in, configure a masked API key, show configured status, and forget either credential. It also loads each configured method's text-model catalog, shows the chosen lead and small models, and lets the user save those choices. Refresh is in the provider header. When both methods are configured, Source Priority in Default Models chooses the preferred source; Subscription is the default until API Key is explicitly selected. The OpenAI tab also has a Daybreak Mode form with Blue and Red choices; the app-server saves the choice, and Blue is the default. The current generic inference path does not apply this setting yet because the access marker must match the requested model. The Default Provider control beside the provider tabs selects a configured primary provider; the initial provider view opens to the saved lead. Lead and model choices open in anchored, scrollable menus inside the window. Escape or an outside click closes a menu; arrow keys, Home, End, and Enter support keyboard selection. The app-server stores credentials and sends only status, sign-in prompts, and account-available model metadata to the desktop. This preview does not yet send inference requests from the desktop.
